# 주간베트남

나트랑 교민(30대 중심)을 위한 주간 베트남 뉴스 사이트. 미니멀 UI(Pretendard, 흑백 + 로즈 포인트, 다크모드 지원). 베트남 · 나트랑/달랏 · 교민생활 · 특산품 네 섹션의 TOP 10을 매주 월요일 아침에 발행한다.

| | 무료 | 이용권 |
|---|---|---|
| 기간 | 주간 | 일간 · 월간 · 1년 · 3년 |
| 순위 | 1~10위 | 11~30위 |

잠금은 서버에서 건다: 이용권이 없으면 11위 이하 데이터를 보내지 않고, 유료 기간 순위는 만들지도 않는다(토큰은 이용권 독자가 열 때만 든다).
국제정세·국내정책·한국 관련·한국인 관광객 관심사에 가중치를 둔다.

## 작동 방식
1. Google News 검색 RSS에서 기사 제목을 모은다 (`lib/rankings.ts`의 `SCOPES`, `PERIODS`).
   - 전국: 영어 3개(일반 / 국제정세 / 국내정책) + 한국어 + 베트남어 검색
   - 나트랑·달랏: 영어·베트남어·한국어 지명 검색
   - RSS는 검색당 약 100건이 한계라 1년은 3개월씩 4구간, 3년은 6개월씩 6구간으로 나눠 검색한다 (`after:` / `before:`)
2. Claude가 제목을 읽고 같은 사건을 묶어 최대 30위까지 매긴다. 1~10위는 2~3문장 요약과 '손님에게 한마디', 11위부터는 한 줄 요약.
   1~10위에는 진행상황을 한눈에 보도록 **현재 상태**(협상 중·시행 중 등), **핵심 수치**(예: 미국 관세율 46% → 20%), **진행 타임라인**(2~5단계)도 붙는다.
   - 핵심 수치는 그 숫자가 근거 기사 제목에 실제로 있을 때만 서버가 남긴다 (`numbersAppearIn`). 제목에 숫자가 없으면 표시하지 않는다.
   - 타임라인 날짜는 AI가 쓴 값이 아니라 연결된 근거 기사의 발행일이다.
3. 화면은 10위까지 보여주고 `더 보기`로 30위까지 펼친다. 각 항목을 누르면 근거 기사 링크가 보인다.

**일주일(기본 화면)** 은 월~일 고정 주간이다. 매주 월요일 06시(베트남 시간)에 서버가 지난주 월~일 뉴스로 전국·나트랑·달랏·교민생활 순위를 자동으로 만들고(`startWeeklyScheduler`, `instrumentation.ts`에서 시작), 다음 월요일까지 그대로 보여준다. 일요일 밤 뉴스와 Google 색인 지연까지 담으려고 월요일 아침에 만든다. 페이지를 몇 번 열어도 토큰을 쓰지 않는다.

**교민생활** (주간 전용, `SCOPES.expat`): 외국인으로서 베트남에서 사는 데 필요한 정책·제도 뉴스. 비자·거주, 부동산, 은행·환율, 사업·상업, 세금, 암호화폐, 외국인 제도(운전면허·보험·학교·혼인·거주신고), 외국인 관련 사건사고. 나트랑·카인호아 정책에 가중치를 주고 별도 검색도 한다. 순위는 화제성(같은 사건 보도 수)과 생활 영향 기준. 베트남어 5개·영어·한국어 검색. 기간 탭과 상관없이 항상 지난주 기준.

**특산품** (주간 전용, `SCOPES.specialty`): 나트랑·달랏 쇼핑 품목 중 침향, 상황버섯, 커피만 다룬다. 기사가 적은 분야라 연구 소식도 넣는다.
- 뉴스: Google News 베트남어 4개(침향 / 상황버섯 / 연구 보도 / 커피)·영어·한국어 검색. 제목에 품목명이 있어야 남긴다(영·한 검색은 베트남 지명도 함께).
- 논문: PubMed(NCBI E-utilities)에서 그 주 월~일에 등록된 침향(agarwood, Aquilaria)·상황버섯(Phellinus linteus) 논문 제목을 최대 30건 받는다. 근거 링크는 PubMed 페이지.
- 커피는 TOP 10 안에 1건만. AI가 어겨도 서버가 나머지 커피를 11위 아래로 내린다(`topCaps`, `applyTopCaps`). 침향·상황버섯이 모자라 10위를 못 채우면 내린 커피는 뺀다.
- Trầm hương은 '침향'으로 번역한다. 프롬프트로 지시하고, '트람흥'처럼 음역된 표기는 서버가 '침향'으로 고친다(`fixTerms`).
- 매일 나오는 시세 기사("Giá cà phê hôm nay …")는 뺀다. 상위 10위 안에 연구는 최대 3건. 연구 항목은 상태가 '연구 발표'.
- 30위를 못 채우면 지난주 순위로 채우고, 그래도 모자라면 지지난주 … 최대 4주 전까지 내려간다. 이번 주 항목이 먼저, 그다음 지난주 순서이고 같은 이야기는 한 번만 넣는다. 가져온 항목에는 '지난주' / 'N주 전' 표시가 붙는다.
- 지난 주 순위는 만들어 둔 것을 다시 쓴다(추가 비용 없음). 서버가 재시작돼 없어졌으면 그 주 기사로 다시 만들므로, 재시작 직후 첫 발행은 AI 호출이 최대 5번(이번 주 + 4주)까지 늘 수 있다.

나머지 기간은 누군가 그 탭을 열었을 때만 만들고(첫 생성 1~3분), 아래 주기 동안 저장해 다시 쓴다. 여러 순위가 동시에 요청돼도 하나씩 만든다. 서버가 재시작(재배포 포함)되면 저장본이 사라지고, 주간 순위는 시작하자마자 다시 만든다.

| 기간 | 검색 구간 | 갱신 |
|---|---|---|
| 일간 (이용권) | when:1d | 열었을 때, 6시간마다 |
| 주간 (무료) | 지난주 월~일 | 매주 월요일 06시 자동 |
| 월간 (이용권) | when:30d | 열었을 때, 2일마다 |
| 1년 (이용권) | 3개월 × 4 | 열었을 때, 14일마다 |
| 3년 (이용권) | 6개월 × 6 | 열었을 때, 30일마다 |

### 토큰 절약
- 비슷한 제목(단어 겹침 50% 이상)은 서버에서 미리 한 줄로 묶고 `x5`처럼 보도 건수만 붙인다. 언론사명은 보내지 않고 날짜는 YYMMDD. 묶은 뒤 최대 350줄(지역 200줄).
- 11~30위는 제목·분류·근거만 받고 요약을 생략한다. 출력 JSON 키는 짧게, 근거 id는 항목당 최대 8개.
- AI 검토 강도: 일간·월간은 low, 주간(주 4회)·1년·3년은 medium.
- 실제 사용 토큰과 비용을 순위마다, 그리고 서버 시작 이후 합계로 화면 하단에 표시한다.

## 환경변수
| 이름 | 기본값 | 설명 |
|---|---|---|
| `ANTHROPIC_API_KEY` | 없음 (없으면 순위 대신 안내 문구) | https://console.anthropic.com 에서 발급 |
| `TOP10_MODEL` | `claude-opus-5-5` | 비용을 줄이려면 `claude-sonnet-5-5` 또는 `claude-haiku-5-5` |
| `PREMIUM_CODES` | 없음 | 이용권 코드 목록, 쉼표 구분. 만료일은 `CODE@2026-12-31`. 목록에서 지우면 즉시 해제 |
| `PREMIUM_SECRET` | 없음 | 쿠키 서명용 긴 임의 문자열. 없으면 재시작마다 독자가 코드를 다시 입력해야 함 |
| `PREMIUM_PRICE_TEXT` | `70,000동` | 이용권 안내에 보일 가격 문구 |
| `PREMIUM_CONTACT` | 없음 | 구매 문의 연락처 (예: 카카오톡 ID) |

| `DATABASE_URL` | 없음 | Railway Postgres 연결 주소. 없으면 로그인·결제가 꺼지고 아래 '구매 문의' 방식으로 동작 |
| `KAKAO_REST_API_KEY` | 없음 | Kakao Developers 앱의 REST API 키 |
| `KAKAO_CLIENT_SECRET` | 없음 | 카카오 앱에서 Client Secret을 켰을 때만 |
| `SITE_URL` | 요청 주소에서 추정 | 사이트 주소 (예: `https://xxx.up.railway.app`). 카카오 Redirect URI는 `SITE_URL/api/auth/kakao/callback` |
| `SESSION_SECRET` | `PREMIUM_SECRET` | 로그인 쿠키 서명용 긴 임의 문자열 |
| `ADMIN_KAKAO_IDS` | 없음 | 운영자 카카오 회원번호 (쉼표 구분). `/admin`에서 송금 확인 요청을 승인 |
| `KAKAOPAY_LINK` | 없음 | 운영자 카카오페이 송금 링크(송금 QR 주소) |
| `KAKAOPAY_AMOUNT` | 가격 문구 | 카카오페이로 받을 금액 표시 (예: `4,000원`) |

## 로그인·결제 (카카오 로그인 + 카카오페이 송금 + 운영자 승인)
카카오페이 자동 결제(API)는 가맹점 계약이 필요해서, 사업자가 없으면 송금을 운영자가 확인하는 방식을 쓴다.
1. 독자가 `PRO 이용권` → `카카오로 시작하기`로 로그인 (닉네임만 받는다)
2. `카카오페이 송금 열기`로 운영자에게 송금하고, 보낸 사람 이름을 적어 `송금했어요`
3. 운영자가 카카오페이 앱에서 입금을 확인하고 `/admin`에서 `승인 (30일)` → 그 회원은 어느 기기에서든 로그인하면 유료 기능이 열린다. 남은 기간이 있으면 그 뒤로 30일 연장
- 예전 이용권 코드(`PREMIUM_CODES`)도 그대로 쓸 수 있다 (`이용권 코드가 있나요?`).
- 승인 요청이 와도 알림은 가지 않는다. `/admin`을 직접 확인해야 한다.

설정 순서
1. Railway 프로젝트에 **+ New → Database → PostgreSQL** 추가 → 사이트 서비스 Variables에 `DATABASE_URL`을 Postgres의 `DATABASE_URL` 참조로 추가 (표는 첫 접속 때 자동 생성)
2. [Kakao Developers](https://developers.kakao.com) → 내 애플리케이션 → 앱 추가 → 플랫폼(Web)에 사이트 주소 등록 → 카카오 로그인 활성화, Redirect URI에 `https://사이트주소/api/auth/kakao/callback` 등록 → 동의항목에서 닉네임 설정 → REST API 키를 `KAKAO_REST_API_KEY`에
3. `SITE_URL`, `SESSION_SECRET`, `KAKAOPAY_LINK`, `KAKAOPAY_AMOUNT` 입력
4. 사이트에서 운영자 본인 카카오로 로그인 → `/admin` 접속 → 화면에 나온 회원번호를 `ADMIN_KAKAO_IDS`에 넣고 재배포

운영자용: 주소 끝에 `#usage`를 붙이면 화면 하단에 AI 사용 토큰·비용이 보인다.

## 한계
- 요약은 기사 제목만 보고 쓴다. 숫자·세부 내용은 근거 기사 원문으로 확인.
- 순위는 AI의 편집 판단이며 객관적 지표가 아니다.
- Google News RSS와 `after:`/`before:` 연산자는 공식 문서화된 API가 아니어서 바뀌거나 막힐 수 있다.

## 실행
```bash
npm install
npm run dev     # http://localhost:3000
```
배포는 Railway (Root Directory: `vietnam-news`).
