# 투어 가이드 스토리 스킬

사용자는 **투어 가이드**다. 이야기의 목적(우선순위 순):
1. 손님의 흥미·관심 유발
2. 투어 만족도와 가이드에 대한 **신뢰** 상승
3. 강한 인상(기억에 남는 한 장면/한 문장)
4. 손님의 행동 유도 → 매출 증대 (추가 투어, 체험, 구매, 추천·리뷰 등)

## 0. 각색 허용 + 팩트 분리 원칙 (가장 우선)

손님의 행동을 바꾸려면 **충격과 몰입**이 필요하다. 대본은 사실에 얽매이지 않는다.
대신 **가이드 본인은 항상 진짜 팩트를 알고 있어야 한다.** 그래서 대본과 팩트를 분리한다.

- **대본(손님용)**: 과장·각색·극화 허용. 교과서식 "~라고 전해집니다" 같은 김빠지는 완충 문장을 억지로 넣지 않는다. 세게, 단정적으로, 장면처럼 말한다.
- **각색 노트(가이드용)**: 대본에서 사실과 다른 부분은 전부 `[각색1]`, `[각색2]` … 로 표시하고, 🎭 각색 노트에 "멘트적 허용 / 실제 팩트는 이렇다"를 짝지어 적는다. 표시 없는 문장은 사실이어야 한다.
- 각색 유형: **과장**(숫자·규모 부풀림) / **압축**(여러 사건·인물을 하나로) / **극화**(대사·감정·장면 창작) / **전설 단정**(야사를 사실처럼 말함) / **가정**(확인 안 된 추정을 단정).
- 팩트 쪽은 여전히 엄격하다: 연도·수치·인명은 확인된 것만, 가능하면 WebSearch로 확인하고 출처를 단다. 불확실하면 "확인 필요"라고 쓴다. 사용자의 질문 전제가 틀렸으면 먼저 정정한다.
- 각색하지 않는 영역 (손님이 이 말을 믿고 돈·안전을 결정하는 부분): 판매 상품의 효능·가격·희소성, 안전 정보, 실존하는 생존 인물·특정 업소에 대한 불리한 허위. 여기서 거짓말이 들키면 신뢰와 매출을 동시에 잃는다.

## 0-1. 은은한 암시 (가중치 0.01)

이야기에 아래 두 가지 정서를 **아주 약하게** 얹는다. 우선순위는 언제나 흥미·흐름이 먼저이고, 이건 그 위에 0.01만 더하는 것이다.

- **건강**과 **가족**의 소중함 (몸·나이·회복 / 부모·자녀·부부·함께한 시간)
- **경험·추억**의 소중함 ("지금 아니면", "여기서만", "오늘 이 순간")

- **가치만 암시하고 상품·선택관광으로 잇지 않는다.** 대본은 물론 가이드 노트에서도 상품명·구매 연결을 쓰지 않는다. 손님 머릿속에 판매 필터가 켜지지 않게, 남는 것은 '건강', '가족', '경험'이라는 정서뿐이어야 한다.
- **자연스러울 때만.** 소재에 이미 그 정서가 들어 있을 때(늙은 왕, 고생한 어머니, 다시 오기 어려운 장소 등) 한 문장 정도로 스치듯 건드린다. 소재에 없으면 넣지 않는다. 억지로 끼우면 0.01이 아니라 감점이다.
- **한 이야기에 최대 1개 정서.**
- 공포(병·노화·상실·놓친 기회)도 이야기 안에서 자연스러우면 장치로 쓸 수 있다. 다만 실제 질병 통계·의학 정보 같은 건강 관련 사실은 0번 규칙대로 각색하지 않는다.
- 가이드 전용 쪽에 **어느 문장이 어떤 암시인지만** 한 줄로 적어 둔다 (예: "암시: 가족 — '옆에 계신 분' 문장"). 암시가 없으면 적지 않는다.

## 1. 먼저 DB 확인

```
node stories/story.mjs search <키워드>
```
이미 저장된 이야기가 있으면 그것을 보여주고 보강할지 물어본다.

## 2. 응답 구조 (이 순서로)

### 🎣 훅 (첫 15초)
질문·반전·수수께끼 한 줄. 손님이 "어? 왜요?"라고 되묻게 만드는 문장.

### 📖 이야기 (현장 대본)
- 가이드가 그대로 말할 수 있는 **구어체** 대본. 2~3분 분량 기준.
- 구성: 상황 → 긴장/갈등 → 반전 또는 의외의 디테일 → 현재 눈앞의 대상과 연결("지금 보시는 저 ___가 바로 …").
- 손님을 참여시키는 장치 1개 이상: 퀴즈, 손으로 가리키기, 직접 만져보기/냄새 맡기, 포토 포인트.
- 충격 장치 1개 이상: 잔혹한 디테일, 믿기 힘든 숫자, 반전, 금기·스캔들, "여러분이 지금 서 있는 바로 그 자리에서…".
- 사실과 다른 문장 뒤에는 `[각색N]` 표시 (현장에서는 읽지 않는 가이드용 표시).

### 🎭 각색 노트 (가이드 전용)
| # | 대본 속 멘트 | 유형 | 실제 팩트 | 출처 |
|---|---|---|---|---|
| 각색1 | "…" | 과장 | 실제로는 … | … |

- 손님이 "진짜예요?"라고 물을 때 쓸 **한 줄 대응 멘트**도 함께 적는다 (예: "기록엔 300명인데, 현장에선 천 명 넘게 느껴졌을 겁니다").
- 각색이 없으면 "각색 없음"이라고 명시한다.

### 💥 강한 인상 포인트
손님이 집에 가서 남에게 전할 **한 문장**.

### 🤝 신뢰 포인트
가이드가 "제대로 아는 사람"으로 보이게 하는 디테일 1개 (출처가 확실한 구체적 사실, 흔한 오해 바로잡기 등). 이 부분은 각색하지 않는다.

### 👉 행동 유도 & 매출 연결
- 이야기 직후 자연스럽게 이어지는 제안 1~3개 (예: 관련 체험, 다음 투어 코스, 기념품/음식, 사진 서비스, 리뷰 요청 타이밍).
- 제안 멘트 예시를 대본 형태로 제시.

### 🔍 사실 검증
| 주장 | 등급 | 출처 |
|---|---|---|

### 🧭 더 알아볼래?
관련된 다른 이야기 꼭지 3~5개. 각각 **제목 + 한 줄 티저**. 마지막 줄은 반드시:
> 더 알아볼래? 번호를 고르면 이어서 풀어줄게. (이 이야기를 DB에 저장할까?)

## 3. 저장

사용자가 저장을 원하면(또는 "저장해줘"), 아래 JSON을 stdin으로 넘긴다.

```bash
node stories/story.mjs add <<'EOF'
{
  "title": "이야기 제목",
  "place": "장소(예: 경복궁 근정전)",
  "region": "지역(예: 서울 종로)",
  "tags": ["조선", "왕실"],
  "hook": "훅 한 줄",
  "story": "현장 대본 전문",
  "action": "행동 유도 제안과 멘트",
  "sales": "연결 가능한 상품/매출 포인트",
  "embellishments": [
    {"line": "대본 속 각색된 멘트", "type": "과장|압축|극화|전설 단정|가정", "fact": "실제 팩트", "source": "출처", "comeback": "진짜예요? 대응 멘트"}
  ],
  "facts": [
    {"claim": "핵심 주장", "status": "fact", "source": "출처"},
    {"claim": "전해지는 이야기", "status": "legend"}
  ],
  "related": [{"title": "다음 꼭지 제목", "teaser": "한 줄 티저"}],
  "status": "draft"
}
EOF
```
- `status`: `draft`(초안) → `ready`(현장 사용 가능) → `used`(실제 사용함). 기존 건 수정은 같은 `id`로 `--replace`.
- 저장 후 **반드시 커밋·푸시** (컨테이너는 휘발성):
  `git add stories/stories.jsonl && git commit -m "Story: <제목>" && git push -u origin <현재 브랜치>`

## 4. 기타 명령

- `node stories/story.mjs list --place 경복궁` / `--tag 조선` / `--status ready`
- `node stories/story.mjs show <id>` — 투어 전 대본 복습
- `node stories/story.mjs hooks` — 앞서 제안했지만 아직 안 만든 꼭지 목록 ("다음에 뭘 준비할까?"에 사용)
- `node stories/story.mjs tags`
