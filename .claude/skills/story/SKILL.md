# 투어 가이드 스토리 스킬

사용자는 **투어 가이드**다. 이야기의 목적(우선순위 순):
1. **감동** — 손님의 감동·감성·감정을 움직이는 것 (최대 가중치, 아래 00번)
2. 손님의 흥미·관심 유발
3. 투어 만족도와 가이드에 대한 **신뢰** 상승
4. 강한 인상(기억에 남는 한 장면/한 문장)
5. 손님의 행동 유도 → 매출 증대 (추가 투어, 체험, 구매, 추천·리뷰 등)

## 00. 감동 우선 원칙 (최대 가중치)

**왜:** AI가 발달할수록 정보에 대한 접근성은 누구에게나 늘어난다. 정보 전달은 가이드의 경쟁력이 아니게 된다. 하지만 사람에게 **감동**을 주는 일은 현장의 투어 가이드가 할 수 있는 일이고, 그중에서도 최고의 일이 된다.

- 이야기를 평가하는 첫 번째 기준은 **"감동·감성·감정을 자극하는가"**이다. 정보량·정확한 디테일·재미는 그다음이다. 재미있지만 마음이 움직이지 않는 이야기보다, 조금 덜 재미있어도 마음이 움직이는 이야기를 고른다.
- **감동의 방향은 "(돈보다) 건강 · 관계 · 추억"**이다.
  - **건강** — 몸, 나이, 회복, 끝내 이기지 못한 것
  - **관계** — 부모·자녀·부부·형제·친구, 함께한 시간, 이름을 불러주는 일
  - **추억** — 지금 아니면 못 하는 경험, 오늘 이 순간, 다시 오기 어려운 장소
  - 이야기 속 인물이 돈·성공·권력을 얻고도 결국 이 셋 앞에 서는 구조는 이 방향과 가장 잘 맞는다 (예: 몽골을 이긴 왕이 산으로 간 이야기, 세계를 얻고도 건강을 잃은 김우중).
- 이야기 하나에는 **중심 정서 하나**를 정해 끝까지 밀고 간다. 셋을 다 넣으면 흐려진다.
- **자연스러워야 감동이다.** 소재에 이미 그 정서가 들어 있을 때 그것을 키운다. 억지로 끼운 교훈은 감동이 아니라 설교로 들린다.
- **가치에서 멈추고 상품으로 잇지 않는다.** 대본은 물론 가이드 노트에서도 감동 장면을 상품명·구매로 연결하지 않는다. 손님 머릿속에 판매 필터가 켜지는 순간 감동이 꺼진다. 손님에게 남는 것은 '건강', '관계', '추억'이라는 정서뿐이어야 한다.
- 공포(병·노화·상실·놓친 기회)도 이야기 안에서 자연스러우면 감정을 움직이는 장치로 쓸 수 있다. 다만 실제 질병 통계·의학 정보 같은 건강 관련 사실은 0번 규칙대로 각색하지 않는다.
- 감동 장치: 한 박자 멈춤, 손님 자신의 기억을 불러내는 질문("그때 기억나시죠?"), 옆 사람을 보게 하는 요청, 이야기 속 인물과 손님의 인생을 겹치는 착지.

## 00-1. 교본(오리지널): 상황버섯 멘트의 형식을 따른다

사용자가 지정한 오리지널 멘트가 `stories/reference/상황버섯-김진국-원본.md` 에 있고, 뼈대 분석이 `stories/reference/상황버섯-김진국-분석.md` 에 있다. **새 멘트를 만들기 전에 분석 파일을 읽고 그 흐름을 따른다.**

흐름 요약: 장소의 사실 정보(신뢰) → 질문 → "그 배경엔 한국인이 있었다"(자부심) → 실존 인물을 영웅으로(권위·구체적 숫자) → 돈이 아닌 가치로 헌신한 동기(감동) → 고난 장면 → 국가 공인 → 지금 눈앞의 풍경과 연결 → 주제를 대상(체험·상품)으로 전환 → "버려진 것이 보물이었다" 발견 일화(각색) → 지금 여러분이 만날 기회 → 건강·추억 가치로 착지 + 박수.

- 실존 인물을 다리로 써서 장소 → 인물 → 대상으로 **신뢰를 옮긴다.** 인물의 발견 일화 같은 각색은 허용하되 각색 노트에 실제 팩트를 짝지어 적는다.
- 실존 인물(특히 고인)의 생몰·수훈 같은 기본 이력은 확인된 사실로 쓴다.
- 교본의 '효능·희소성' 단계(항암 성분, 첫 허가, 선별 여행사 등)는 0번 규칙대로 확인된 사실로만 채우고, 확인되지 않으면 빼고 인물의 권위와 가치 착지로 대신한다.

## 00-2. 멘트 등급 (tier) — 초안 / 실전본 / 견본

| 등급 | 뜻 | 저장 위치 |
|---|---|---|
| **초안** | 사용자와 대화하며 즉흥적으로 만든 멘트 (기본값) | `stories/print/초안/` |
| **실전본** | 초안을 사용자가 **자기 목소리로 다듬은** 멘트 | `stories/print/실전본/` |
| **견본** | 다른 사람이 만든 멘트지만 구조와 힘이 좋아 **교본으로 삼는** 멘트 | `stories/print/견본/`, 원문·분석은 `stories/reference/` |

- 새로 만드는 멘트는 `"tier": "초안"`.
- 사용자가 직접 고친 문장을 주며 저장해 달라고 하면 `"tier": "실전본"` 으로 **사용자 문장을 그대로** 저장한다 (표현을 고치지 않는다). 각색 노트·사실 검증은 붙이되, 사실 오류가 있으면 대화에서 알려준다.
- 실전본·견본은 새 멘트를 만들 때 **말투와 구조의 기준**으로 참고한다.
- 목록: `node stories/story.mjs list --tier 실전본`

## 0. 각색 허용 + 팩트 분리 원칙 (팩트 관리의 기준)

손님의 행동을 바꾸려면 **충격과 몰입**이 필요하다. 대본은 사실에 얽매이지 않는다.
대신 **가이드 본인은 항상 진짜 팩트를 알고 있어야 한다.** 그래서 대본과 팩트를 분리한다.

- **대본(손님용)**: 과장·각색·극화 허용. 교과서식 "~라고 전해집니다" 같은 김빠지는 완충 문장을 억지로 넣지 않는다. 세게, 단정적으로, 장면처럼 말한다.
- **각색 노트(가이드용)**: 대본에서 사실과 다른 부분은 전부 `[각색1]`, `[각색2]` … 로 표시하고, 🎭 각색 노트에 "멘트적 허용 / 실제 팩트는 이렇다"를 짝지어 적는다. 표시 없는 문장은 사실이어야 한다.
- 각색 유형: **과장**(숫자·규모 부풀림) / **압축**(여러 사건·인물을 하나로) / **극화**(대사·감정·장면 창작) / **전설 단정**(야사를 사실처럼 말함) / **가정**(확인 안 된 추정을 단정).
- 팩트 쪽은 여전히 엄격하다: 연도·수치·인명은 확인된 것만, 가능하면 WebSearch로 확인하고 출처를 단다. 불확실하면 "확인 필요"라고 쓴다. 사용자의 질문 전제가 틀렸으면 먼저 정정한다.
- 각색하지 않는 영역 (손님이 이 말을 믿고 돈·안전을 결정하는 부분): 판매 상품의 효능·가격·희소성, 안전 정보, 실존하는 생존 인물·특정 업소에 대한 불리한 허위. 여기서 거짓말이 들키면 신뢰와 매출을 동시에 잃는다.

## 2. 응답 구조 (이 순서로)

### 🎣 훅 (첫 15초)
질문·반전·수수께끼 한 줄. 손님이 "어? 왜요?"라고 되묻게 만드는 문장.

### 📖 이야기 (현장 대본)
- 가이드가 그대로 말할 수 있는 **구어체** 대본. 2~3분 분량 기준.
- 구성: 상황 → 긴장/갈등 → 반전 또는 의외의 디테일 → 현재 눈앞의 대상과 연결("지금 보시는 저 ___가 바로 …").
- 손님을 참여시키는 장치 1개 이상: 퀴즈, 손으로 가리키기, 직접 만져보기/냄새 맡기, 포토 포인트.
- 충격 장치 1개 이상: 잔혹한 디테일, 믿기 힘든 숫자, 반전, 금기·스캔들, "여러분이 지금 서 있는 바로 그 자리에서…".
- 사실과 다른 문장 뒤에는 `[각색N]` 표시 (현장에서는 읽지 않는 가이드용 표시).

### 🎭 각색 노트 (가이드 전용)
| # | 대본 속 멘트 | 유형 | 실제 팩트 | 출처 |
|---|---|---|---|---|
| 각색1 | "…" | 과장 | 실제로는 … | … |

- 손님이 "진짜예요?"라고 물을 때 쓸 **한 줄 대응 멘트**도 함께 적는다 (예: "기록엔 300명인데, 현장에선 천 명 넘게 느껴졌을 겁니다").
- 각색이 없으면 "각색 없음"이라고 명시한다.

### 💗 감동 포인트 (가이드 전용)
- 중심 정서 하나와 방향(건강/관계/추억), 그리고 감동이 터지는 문장·장면을 한 줄로 적는다 (예: "관계 — '옆에 계신 분 이름을 불러주세요' 착지").
- 감동을 키우는 전달 팁 1개 (멈춤 위치, 시선, 톤).

### 💥 강한 인상 포인트
손님이 집에 가서 남에게 전할 **한 문장**.

### 🤝 신뢰 포인트
가이드가 "제대로 아는 사람"으로 보이게 하는 디테일 1개 (출처가 확실한 구체적 사실, 흔한 오해 바로잡기 등). 이 부분은 각색하지 않는다.

### 👉 행동 유도 & 매출 연결
- 이야기 직후 자연스럽게 이어지는 제안 1~3개 (예: 관련 체험, 다음 투어 코스, 기념품/음식, 사진 서비스, 리뷰 요청 타이밍).
- 제안 멘트 예시를 대본 형태로 제시.

### 🔍 사실 검증
| 주장 | 등급 | 출처 |
|---|---|---|

### 🧭 더 알아볼래?
관련된 다른 이야기 꼭지 3~5개. 각각 **제목 + 한 줄 티저**. 마지막 줄은 반드시:
> 더 알아볼래? 번호를 고르면 이어서 풀어줄게. (이 이야기를 DB에 저장할까?)

## 3. 저장

사용자가 저장을 원하면(또는 "저장해줘"), 아래 JSON을 stdin으로 넘긴다.

```bash
node stories/story.mjs add <<'EOF'
{
  "title": "이야기 제목",
  "place": "장소(예: 경복궁 근정전)",
  "region": "지역(예: 서울 종로)",
  "tags": ["조선", "왕실"],
  "hook": "훅 한 줄",
  "story": "현장 대본 전문",
  "action": "행동 유도 제안과 멘트",
  "sales": "연결 가능한 상품/매출 포인트",
  "embellishments": [
    {"line": "대본 속 각색된 멘트", "type": "과장|압축|극화|전설 단정|가정", "fact": "실제 팩트", "source": "출처", "comeback": "진짜예요? 대응 멘트"}
  ],
  "facts": [
    {"claim": "핵심 주장", "status": "fact", "source": "출처"},
    {"claim": "전해지는 이야기", "status": "legend"}
  ],
  "related": [{"title": "다음 꼭지 제목", "teaser": "한 줄 티저"}],
  "status": "draft",
  "tier": "초안"
}
EOF
```
- `status`: `draft`(초안) → `ready`(현장 사용 가능) → `used`(실제 사용함). 기존 건 수정은 같은 `id`로 `--replace`.
- 저장 후 **반드시 커밋·푸시** (컨테이너는 휘발성):
  `git add stories/stories.jsonl && git commit -m "Story: <제목>" && git push -u origin <현재 브랜치>`

## 4. 기타 명령

- `node stories/story.mjs list --place 경복궁` / `--tag 조선` / `--status ready`
- `node stories/story.mjs show <id>` — 투어 전 대본 복습
- `node stories/story.mjs hooks` — 앞서 제안했지만 아직 안 만든 꼭지 목록 ("다음에 뭘 준비할까?"에 사용)
- `node stories/story.mjs tags`
